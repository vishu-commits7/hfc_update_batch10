# 4.5 Testing the apex_pro subscription

Written from the code on 10 Nov 2026 (`functions/src/billing.ts`, `src/lib/billing.ts`,
`ApexBillingPlugin.java`, `PaywallSheet.tsx`). Play Console menu names change now and then; the names below
are how I know them, so look for the nearest match. Nothing here has been run.

## How it works (so the checks make sense)

1. The paywall asks Google Play for the offers of product `apex_pro` and shows Play's own prices.
2. After a purchase the app sends the purchase token to the `verifyPurchase` Cloud Function.
3. The function asks Google Play if the token is valid, acknowledges it, and writes on `users/{uid}`:
   `proUntil` (expiry, milliseconds), `proState`, `proProduct`. It also writes `playTokens/{hash}` so one
   purchase belongs to one app account.
4. `getEntitlement` tells the app whether the user is Pro. While `BILLING_ENABLED` is not `true`, it says
   everyone is Pro, but purchases are still verified and recorded. **So you can test the whole purchase with
   billing switched off.**
5. Every time the app opens, it re-checks any active Play subscription (renewals, cancellations).
6. The server gives 3 extra days after `proUntil` before Pro is removed (`GRACE_MS`).

## A. One-time setup

1. **Upload a build to the Internal testing track** (Testing > Internal testing). Play Billing only works for a build installed from Play, signed with your upload key, with the same package name `com.homefitnesscoach.app`.
2. **Create the subscription** (Monetise > Products > Subscriptions): product ID exactly `apex_pro`.
   - Base plan `monthly`: auto-renewing, 1 month. Base plan `yearly`: auto-renewing, 1 year. Set prices (INR at least). Activate both.
   - Optional: on `yearly`, add an offer with a free trial phase (for example 7 days), for new customers. The paywall shows "7-day free trial, then ..." only if this exists.
3. **Add licence testers** (Settings > Licence testing): the Gmail addresses that will test. Add the same people as testers on the Internal track, open the opt-in link on the phone, and install from Play.
4. **Let the server talk to Google Play.** This is where it usually fails.
   - In Google Cloud Console for project `fitness-app-1e5f0`: enable **Google Play Android Developer API**.
   - Find the service account your functions run as: Cloud Console > Cloud Run (or Cloud Functions) > `verifypurchase` > Security / Details > Service account. For 2nd-gen functions it is normally `PROJECT_NUMBER-compute@developer.gserviceaccount.com`.
   - In Play Console > Users and permissions > Invite new users: add that service account email. Give it, for this app: **View app information**, **View financial data, orders and cancellation survey responses**, **Manage orders and subscriptions**.
   - Wait. New permissions can take hours (sometimes a day) to work. A known nudge: edit and save any subscription detail in Play Console.
5. `functions/.env`: `PLAY_PACKAGE=com.homefitnesscoach.app`. Leave `BILLING_ENABLED=false` for now. Deploy functions.

## B. Test steps

The paywall only opens after 3 finished workouts, so finish 3 short workouts on the test account first.

| # | Do | Expect in the app | Check on the server |
|---|---|---|---|
| 1 | Open the paywall (Today card Pro line, or the Premium button) | Yearly first with "Best value", price in INR, trial line if you made the offer, "Restore purchases" button | none |
| 2 | Buy Monthly with "Test card, always approves" | Play sheet says it is a test purchase; afterwards the sheet shows "You're Pro" with a date | Firestore `users/{uid}`: `proUntil` in the future, `proState` = `SUBSCRIPTION_STATE_ACTIVE`, `proProduct` = `apex_pro`. A new `playTokens/{...}` doc with your uid |
| 3 | Look at the function log | none | Cloud Logging > `verifypurchase`: a 200, no error |
| 4 | Wait 6 minutes, do nothing | none | Play Console > Order management: the order is **not** refunded. (Test purchases that are not acknowledged are refunded after about 3 minutes, so this proves the acknowledge call worked) |
| 5 | Close and reopen the app after the first renewal (test monthly renews about every 5 minutes) | still Pro | `proUntil` has moved later |
| 6 | Cancel in Google Play > Payments and subscriptions | still Pro until the period ends | after reopening: `proState` = `SUBSCRIPTION_STATE_CANCELED`, `proUntil` unchanged |
| 7 | Wait for the period to end, reopen | (with billing off, nothing visible changes) | `proState` = `SUBSCRIPTION_STATE_EXPIRED`, `proUntil` in the past |
| 8 | Buy Yearly on a second test account, with the trial offer | button reads "Start 7-day free trial"; Play shows the trial | same fields; `proUntil` is the end of the trial |
| 9 | Clear the app's data (or reinstall), sign in to the same app account, paywall > Restore purchases | "Pro restored." | `proUntil` in the future again |
| 10 | On the same phone and Google account, sign in to a **different** app account, Restore purchases | "No active subscription found for this Google account." | function log shows `permission-denied` ("linked to another account"); the second user has no `proUntil` |
| 11 | Buy with "Test card, always declines" | an error message, "You haven't been charged" style; no Pro | nothing written |
| 12 | Refund and revoke the order in Play Console > Order management, reopen the app | (with billing off, nothing visible) | `proState` no longer active, `proUntil` at or before now |

Test renewal timing (set by Google): 1 month renews in about 5 minutes, 1 year in about 30 minutes, up to 6 times, then it cancels itself.

### If `verifyPurchase` fails

| What you see | Meaning |
|---|---|
| App: "Couldn't reach Google Play. Try again in a minute." Log: 401 or 403 | The service account has no access yet (step A4), or the API is not enabled |
| App: "Google Play doesn't recognise this purchase." Log: 400/404/410 | Wrong `PLAY_PACKAGE`, or the token is from a different app or an expired test purchase |
| App: "This purchase is linked to another account." | Working as designed (test 10) |
| Paywall: "Pro isn't available to buy right now." | Play returned no offers: product not active, wrong product ID, app not installed from Play, or the account is not a tester |
| Paywall: "Couldn't load Pro plans from Google Play." | Billing could not connect: no Play Store on the device, or no network |

## C. Before setting `BILLING_ENABLED=true`

1. Tests 1 to 12 pass on the **production** Firebase project and the real package, not just a test project.
2. Turn it on in a test project first and check what a non-subscriber sees: the Today card shows the generic plan line and the Pro prompt; the AI generator shows its upgrade screen (only after 3 workouts); a subscriber sees the plan reason and the 3-day outlook.
3. The paywall's list of what Pro includes is true. Today the server only gates the plan reason and 3-day outlook; the app gates the AI generator and the coaching hub. If that list is wrong, fix the paywall text first.
4. Decide about the 3-day grace. A refunded or expired user keeps Pro for 3 more days. That is kind for payment hiccups and generous for refunds.
5. There are no real-time notifications from Google Play. The server only learns about a renewal, cancellation or refund when that user next opens the app. Fine at launch size; add Real-time developer notifications later.
6. Everyone has had Pro for free until now. The day you switch, existing users lose the plan reason, outlook and AI generator. Tell them first, or give existing users a free period.
7. Play Console: payments profile and tax details complete, prices set for every country you sell in, subscription description filled in.
8. Listing and privacy policy mention the subscription and how to cancel (see 4.4).
9. The store build contains this paywall (Restore purchases button, trial line). Older builds show the old one.
10. After switching: buy once with a real card on a real account, check `proUntil`, then refund yourself.
