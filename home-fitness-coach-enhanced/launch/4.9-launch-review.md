## Blockers (must be done before production)

1. **The Android app has never been compiled.** Java and Gradle changes from Batches 12, 20, 32, 43, 46 and 47 (Health Connect, billing, audio focus, device id, in-app review, App Check) have only been written. A build error or a crash on launch is possible. Step: `npm run build`, `npx cap sync android`, build in Android Studio, install on a phone.
2. **Nothing has run on a device.** Every batch note ends "not tested on a device". First-session flow, camera rep counting, push, offline queue, voice coaching, share sheet, QR scan: all unconfirmed.
3. **Rules and functions are not deployed, and the rules were never run in the emulator.** Until `firebase deploy --only firestore:rules,firestore:indexes,storage,functions` succeeds, the app in the field would talk to old rules. New indexes (ghosts, feedback) need time to build.
4. **No public privacy-policy URL** (Play requirement). The policy exists only inside the app.
5. **No web page for account deletion requests** (Play requirement for apps with accounts). In-app deletion exists.
6. **The in-app privacy text makes claims the code does not keep** (from `4.4-play-console-declarations.md`): "camera feeds are never uploaded" (Arena video and reels do), "zero third-party tracking" (Firebase Analytics and Crashlytics are in), "encrypted cloud sync" (not end-to-end). Fix the text before the Data safety form, or the form and the app will disagree.
7. **Release signing is not set up on this machine.** `android/keystore.properties` and a keystore are missing, so a release build would be unsigned. (If they live on another machine, this is done.)
8. **Play Console forms**: Data safety, Health apps declaration, Advertising ID declaration (the `AD_ID` permission is not removed in the manifest), target audience 13+, content rating, support email. Drafts are in `4.4`.
9. **Closed-testing requirement**, if your Play account is a newer personal account: 12 testers for 14 days before production. This sets the earliest possible date.

## Known limits that are accepted, not bugs

- Anti-cheat stops impossible counts, not dishonest ones: taps are not proof of a rep, and a second account or a reset phone gets round the pair and device limits (Batch 41, 43).
- Ghosts exist only for first-to-N, single-exercise matches; leagues need the user to open the League tab to join; daily challenge is taps only.
- A moderator cannot remove a chat message; it can only be reported.
- Cost estimates in `COSTS.md` are partly guesses until real usage exists.
